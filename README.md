## ✨ What's inside

- **📖 Pokédex** — 1,300+ Pokémon with stats, types, abilities, full learnsets, evolution lines, type match-ups, shiny toggle and animated battle sprites. Mega / Primal / Gigantamax forms included.
- **🌍 Regions & maps** — Sinnoh, Jvaloh, Hoenn & Kanto. Interactive world maps and per-location spawn tables (rarity · time · method · level).
- **🎯 "Where to catch"** — every route a Pokémon appears on, plus special acquisition methods (bosses, events, mining, sanctums…).
- **🎒 Item / Mount / Cosmetic dex** — searchable galleries with "where to get" sources (NPC shops, wild drops, trades).
- **🔎 Global search** — one search box (and `Ctrl/⌘ + K` anywhere) across Pokémon, items, mounts, cosmetics, locations and regions.
- **🌐 4 languages** — English, Español, 中文, Português, switchable at runtime.
- **⚡ Fast** — fully prerendered (~1,750 static routes), self-hosted WebP artwork, served from the edge.

## 📂 Project structure

```
PBO-Atlas/
├─ src/app/
│  ├─ core/        # data loaders (SSR/browser), i18n, domain models, pure utils
│  ├─ shared/      # reusable components, directives, the global search
│  ├─ layout/      # header, footer, language toggle, search trigger
│  └─ features/    # pokedex · region · game (items/mounts/cosmetics) · home · feedback
├─ scripts/        # the data pipeline (*.mjs) + shared lib/
├─ data/           # source JSON produced by the pipeline (committed)
└─ public/data/    # per-page JSON served to the client (one small file per entity)
```

The app never ships one giant JSON: `build-page-data` slices everything into small per-entity files under `public/data/`, so each page fetches only what it needs.

## 🔧 Getting started

```bash
npm install

```

## 🔄 The data pipeline

All game data is generated by scripts and committed to `data/`. Sourced from the
[official PBO forum](https://forums.pokemonblazeonline.com/), the game client
and [PokeAPI](https://pokeapi.co/).

```bash
npm run data       # runs the full chain end-to-end
```

…or run a single stage:

| Script | Builds |
|---|---|
| `npm run scrape` | wild spawns per route (forum) |
| `npm run pokedex` | dex entries, stats, learnsets |
| `npm run moves` | move data |
| `npm run extras` | items, mounts, cosmetics, natures |
| `npm run maps` | world-map marker coordinates |
| `npm run search-index` | the global search index |
| `npm run page-data` | splits everything into `public/data/**` |
| `npm run artwork` | downloads & converts official artwork to WebP |

Some data can't be scraped cleanly and is **hand-curated overlays**, merged in at build time (so a re-scrape never wipes it):

- `data/acquisitions.json` — special "how to obtain" methods (legendaries, evolutions…)
- `data/item-sources.json` — "where to get" for items (shops & drops)
- `data/extra-spawns.json` — special-area encounters (e.g. the sanctum legendaries)

## 🤝 Contributing

Contributions are very welcome — especially **data fixes** (spawns, levels, sources) since the game keeps updating!

1. **Fork** the repo and create a branch: `git checkout -b my-fix`.
2. **Run it** locally with `npm start` and make your change.
3. **Spot a wrong/missing spawn or source?** Edit the curated overlay JSON above (no scraping needed) — e.g. add an entry to `data/extra-spawns.json`, then `npm run page-data` to regenerate.
4. **Build** to make sure everything compiles: `npm run build`.
5. Open a **Pull Request** describing the change (and a forum link for data, if you have one).

**Code conventions:** standalone components, signals over RxJS in components, `ChangeDetectionStrategy.OnPush`, `@if/@for` control flow, Tailwind classes in templates, path aliases (`@core/*`, `@shared/*`, `@features/*`, `@layout/*`).
